# Мост для эфира (v0.6) — как это работает

Мост — это способ, которым **событие стрима превращается в действие внутри мира**: зритель подписался →
через секунду на чердаке звенит колокол, в чате появляется кликабельная карточка, а на свободный постамент
рядом с алтарём встаёт новая фигурка.

Главный принцип: **мод ничего не знает про Twitch и YouTube**. Он не ходит в интернет, не хранит ключи
и не требует OAuth. Он просто умеет принимать «почту» от того, кто уже знает про события, — от Streamer.bot,
MixItUp, вашего скрипта или OBS-плагина. Такие программы уже подключены к платформам и умеют либо писать
файл, либо дёргать `http://127.0.0.1:8765`.

```
Twitch / YouTube / Boosty
        │  (событие: подписка, гифт, донат, рейд)
        ▼
Streamer.bot / MixItUp / твой скрипт        ← знает про OAuth и API
        │
        ├── пишет файл в  config/chrdk_pantheon/inbox/*.json
        └── POST http://127.0.0.1:8765/event
        ▼
Мод «Чердак Бессмертных»                    ← знает только про чердак
        │  разбор события → проверки → ритуал
        ▼
Фигурка на постаменте · звон · искры · запись в летопись · Книга Имён
```

## 1. Два входных канала

Оба канала можно включить вместе, по отдельности или выключить оба — тогда чердак живёт как раньше,
на командах и печатях.

### Канал А: папка входящих (работает всегда, не требует сети)

* Путь: `config/chrdk_pantheon/inbox/` (создаётся сам при первом запуске).
* Формат: `.json` (структурированно) или `.txt` (одной строкой, для ручных проверок).
* Как обрабатывается: мод раз в секунду смотрит папку, берёт файлы по алфавиту, обрабатывает,
  затем **переносит** в `inbox/archive/processed/` (или `failed/`, если событие не разобралось —
  рядом кладётся `<имя>.reason.txt` с причиной). Файлов не удаляем: в архиве всегда видно, что приходило.
* Порядок гарантирован префиксом в имени: `event-2026-10-08T21-15-03-123.json` — так события эфира
  не перепутаются местами, даже если система записала их одновременно.
* Пока мир закрыт, файлы просто **копятся**. Когда зайдёшь в мир, мод разберёт очередь и скажет:
  «Пока тебя не было, на чердак пришли 5 имён: Kolya, …».

### Канал Б: локальный порт (для «живого» эфира)

* Адрес: `POST http://127.0.0.1:8765/event` (порт настраивается; по умолчанию 8765).
* Слушает **только 127.0.0.1** — то есть доступен лишь программам на том же компьютере.
  Наружу ничего не открывается, брандмауэр видит только локальный сокет.
* Реализация без зависимостей: маленький сервер на `ServerSocket` в отдельном потоке демона,
  разбор минимального HTTP (метод, `Content-Length`, тело). Поток ничего не делает с миром напрямую —
  он кладёт событие в очередь, а очередь разбирает игровой цикл в главном потоке. Это важно:
  никаких обращений к миру из чужого потока, никаких «залипаний» тика.
* Ответы: `200 {"ok":true,"queued":"Kolya"}` — принято; `400` — кривой JSON; `401` — включён токен
  и он не совпал; `409` — такое событие уже было (дубликат); `503` — очередь переполнена.
* Если порт занят (другая программа) — мод пишет в чат предупреждение и продолжает работать,
  файловый канал при этом никуда не пропадает. В `bridge.json` можно сменить порт.

## 2. Формат события

### JSON (для HTTP и файлов)

```json
{
  "type": "sub",
  "nick": "Kolya",
  "platform": "twitch",
  "months": 12,
  "amount": 0,
  "tier": 0,
  "message": "привет с чердака",
  "id": "twitch-sub-8912f0"
}
```

| Поле | Обязательное | Что значит |
|---|---|---|
| `type` | да | `follow`, `sub`, `resub`, `gift`, `donation`, `raid`, `message`, `remove` |
| `nick` | да | ник/имя зрителя — оно же попадёт на табличку и в летопись |
| `platform` | нет | откуда пришёл: `twitch`, `youtube`, `boosty`, `vkplay`, `свой` — попадает в поле «источник» |
| `months` | нет | сколько месяцев подписки (для `sub`/`resub`) — влияет на тир |
| `amount` | нет | сумма доната/бита в условных единицах (рубли/центы — как договоришься со скриптом) |
| `tier` | нет | если хочется задать тир вручную (1–5) — перебивает расчёт по месяцам и сумме |
| `message` | нет | сообщение зрителя: попадёт в чат и в карточку подписчика |
| `id` | нет | идентификатор события для защиты от дублей (если платформа его даёт) |

Неизвестные поля игнорируются, так что можно прислать хоть весь объект Streamer.bot — важно лишь,
что нужные поля на месте. Поле `type` понимает и русские синонимы: `подписка`, `донат`, `гифт`, `рейд`.

### Текст (для быстрых проверок и bash-скриптов)

```
follow Kolya
sub Kolya 12 twitch
donate Kolya 500 привет с чердака
raid Kolya 42
remove Kolya
```

Формат: `тип ник [месяцы|сумма] [платформа] [сообщение]`. Тип можно писать и по-русски.

## 3. Что происходит в мире (ритуал «явление»)

Обработка одного события идёт по шагам, и каждый шаг что-то делает со миром:

1. **Разбор и дедупликация.** Собираем поля, проверяем `id`/«ник+тип+минута» против списка последних
   256 событий. Повтор молча отбрасывается (стрим-боты иногда дублируют события).
2. **Летопись.** Если имени нет — вписываем (`source` = платформа, `addedAt` = момент события),
   если есть — обновляем тир, если он вырос («Kolya: тир 3 → 4»), и оживляем (`active = true`).
   Тип `remove` — наоборот, «тушим» фигурку: она остаётся на месте, но гаснет и не считается в ауре.
3. **Тир.** Если `tier` не задан явно, он считается по таблице:

| Событие | Правило | Тир |
|---|---|---|
| `sub` / `resub` | 1–2 мес | 1 |
| | 3–5 мес | 2 |
| | 6–11 мес | 3 |
| | 12–23 мес | 4 |
| | 24+ мес | 5 |
| `donation` | до 99 | 1 |
| | 100–499 | 2 |
| | 500–999 | 3 |
| | 1000–4999 | 4 |
| | 5000+ | 5 |
| `follow`, `raid`, `gift`, `message` | всегда | 1 (зато быстро, «встал на полку») |

Пороги — в конфиге, можно переписать под свои единицы.
4. **Явление.** Мод ищет **свободный постамент** в радиусе `radius` (по умолчанию 32 блока) от ближайшего
   **Чердачного алтаря** — алтари мод запоминает при установке, как и святилища. Найден → фигурка встаёт
   на него: печатается свечение (`END_ROD`), пыль, звук наковальни и колокола, пост обновляется.
   Не найден → событие всё равно попадает в летопись, а зритель попадает в очередь «на подходе»
   и встанет на постамент сам, как только освободится (например, снимешь фигурку или поставишь новый).
5. **Объявление.** В чат уходит кликабельная строка:
   `✦ Kolya явился на чердак (twitch · подписка 12 мес → тир 4) · фигурка встала на постамент 128, 64, -37`,
   где клик по имени открывает карточку подписчика (тир, источник, дары, «потушить»), а клик по координатам —
   «подойти» (телепорт‑команда `[посмотреть]`, если включена в конфиге). Сообщение идёт всем в мире.
6. **Большие события — по-другому.** `raid` и крупные донаты (тир 4–5) сопровождаются **фейерверком**
   в зале и усиленным звоном; `gift` (гифт-саб) поднимает на постамент сразу нескольких — каждому
   из подарочных подписчиков, если бот их присылает списком.
7. **Вехи и аура.** После вставки мод проверяет вехи (10/50/100/500/1000) — при переходе через рубеж
   событие в мире ровно то же, что и при импорте, так что вехи не «теряются» между эфирами.
   Новая фигурка сразу участвует в Ауре Пантеона.

Ничего необратимого ритуал не делает: постаменты не создаются и не ломаются, блоки не двигаются.
Если свободных постаментов нет — мир остаётся как был, а событие просто записано и опубликовано.

## 4. Конфиг

`config/chrdk_pantheon/bridge.json` (создаётся с комментариями-умолчаниями при первом запуске):

```json
{
  "enabled": true,
  "inbox": true,
  "port": 8765,
  "bind": "127.0.0.1",
  "token": "",
  "spawn_mode": "pedestal_or_chat",
  "radius": 32,
  "types": ["follow", "sub", "resub", "gift", "donation", "raid", "message", "remove"],
  "ignore": [],
  "min_announce_tier": 1,
  "effects": true,
  "tier_rules": {
    "months": [2, 5, 11, 23],
    "amount": [99, 499, 999, 4999]
  },
  "announce_offline": true
}
```

| Ключ | Смысл |
|---|---|
| `inbox` | включён ли файловый канал |
| `port`, `bind` | порт и адрес прослушивания (по умолчанию только локально) |
| `token` | необязательный общий секрет: если задан, событие должно прийти с заголовком `X-Attic-Token` или полем `token` |
| `spawn_mode` | `pedestal_or_chat` (встать на постамент, иначе только запись и чат), `chat` (никогда не занимать постаменты), `pedestal` (не трогать мир, если постамента нет — просто пропустить) |
| `radius` | как далеко от алтаря искать свободные постаменты |
| `types` | какие события вообще пускать на чердак |
| `ignore` | ники-исключения (например, боты) |
| `min_announce_tier` | кого не объявлять в чате (мелочь пусть просто встаёт на полку) |
| `effects` | звук/искры/фейерверк (выключается, если играешь в наушниках и не хочешь звона) |
| `tier_rules` | пороги тиров: четыре числа для месяцев и суммы |
| `announce_offline` | говорить ли, сколько имён накопилось, пока мир был закрыт |

## 5. Команды

| Команда | Что делает |
|---|---|
| `/attic bridge` | состояние: включён ли мост, слушает ли порт, сколько событий обработано и ждёт, где папка входящих |
| `/attic bridge on` / `off` | включить/выключить приём (мир перезапускать не надо) |
| `/attic bridge port 8765` | сменить порт на лету (писать `bridge.json` руками тоже можно) |
| `/attic bridge test Kolya sub 12` | прогнать событие «как с эфира» — удобно проверять ритуал, не подключая бота |
| `/attic pending` | очередь «на подходе»: кто ждёт свободного постамента и где свободные постаменты есть |
| `/attic here` | сколько алтарей и свободных постаментов мод видит (и в каком радиусе) |

Плюс мелочь: `/attic pending place <ник>` — вручную поставить ждущего на любой конкретный постамент,
на который смотришь (для случаев, когда хочется расставить людей красиво, а не как попало).

## 6. Подключение Streamer.bot (самое частое)

Тебе нужны два действия в Streamer.bot — на подписку и на рейд (остальные — копии).

**Вариант «HTTP» (событие сразу улетает в мир):**

1. Trigger: `Twitch → Sub` (и `Follow`, `Raid`, `Cheer`, если нужно).
2. Sub-Action: `Core → Network → HTTP Request`.
3. Method: `POST`, URL: `http://127.0.0.1:8765/event`,
   Content Type: `application/json`.
4. Body:

```json
{
  "type": "sub",
  "nick": "%userName%",
  "platform": "twitch",
  "months": "%cumulativeMonths%",
  "message": "%message%",
  "id": "sub-%userName%-%cumulativeMonths%-%eventTime%"
}
```

**Вариант «файл» (если игра на одном компьютере, а бот — на том же или в докере):**

Sub-Action `Core → Files → Write File`: путь `…\config\chrdk_pantheon\inbox\event-$%eventTime%.json`,
содержимое — тот же JSON. Поле `id` не нужно: имена файлов уже уникальны.

Минимум, что стоит прислать — `type` и `nick`; всё остальное улучшает ритуал (тир, сообщение, источник).

**MixItUp / StreamElements / свой бот** — то же самое: найди действие «HTTP Request» / «Webhook» и отправь
такой же JSON на `127.0.0.1:8765`. Ограничение одно: программа должна быть на том же компьютере,
что и игра (или пробросить порт на себя через SSH — тогда включи `bind: "0.0.0.0"` осознанно и поставь `token`).

Ожидаемая задержка: **до одной секунды** от события до звонка в зале (папка опрашивается раз в секунду,
порт — мгновенно, но событие всё равно встаёт в очередь и разбирается на ближайшем тике).

## 7. Что мост сознательно НЕ делает

* **Не подключается к Twitch/YouTube сам.** OAuth-токены, EventSub, WebSub, квоты — это отдельный мир,
  который ломается от смены политики платформ. Пусть этим занимается Streamer.bot, а чердак останется чердаком.
* **Не открывает порт наружу** по умолчанию и не делает исходящих запросов — в игре вообще нет сетевого кода,
  кроме чтения локального сокета.
* **Не создаёт и не ломает блоки** под фигурки: место для подписчика выбирает игрок, мод только занимает
  уже поставленные постаменты.
* **Не удаляет события при ошибке** — непонятный файл едет в `archive/failed/` с причиной, чтобы можно было
  посмотреть глазами и поправить.

## 8. План реализации v0.6 (чеклист)

1. `bridge/BridgeEvent` — запись события (Codec для JSON) + разбор текстовой формы.
2. `bridge/BridgeConfig` — чтение/запись `bridge.json` (Gson уже есть в 26.3), значения по умолчанию.
3. `bridge/EventQueue` — очередь, лимит на тик (например, 4 события), дедупликация последних 256 событий.
4. `bridge/InboxWatcher` — обход папки раз в секунду, перенос в `archive/processed|failed`.
5. `bridge/LocalServer` — `ServerSocket` в демон-потоке, минимальный HTTP, ответы 200/400/401/409/503.
6. `gameplay/Ceremony` — ритуал: тир → летопись → поиск свободного постамента у алтаря → эффекты → объявление.
7. Учёт алтарей (`trackAltar`/`untrackAltar`) и очередь «на подходе» (`PantheonData`), автопостановка
   при освобождении постамента.
8. Команды `/attic bridge …`, `/attic pending`, `/attic here`.
9. `tools/bridge_send.py` — скрипт-отправитель для проверки: `python3 tools/bridge_send.py Kolya sub --months 12`.
10. Тесты в CI: юнит-тестов у нас нет, поэтому — «сухой» прогон в diag (разбор примеров JSON/текста)
    и ручная проверка через `/attic bridge test`.
11. README: раздел «Эфир в прямом эфире» со скриншотом-инструкцией для Streamer.bot, DESIGN: отметка v0.6.

**Порядок работы:** пункты 1–7 в один заход (это ядро), 8–9 сразу за ними, 10–11 и релиз.
